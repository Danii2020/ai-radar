## Notes for the auditor

- **The two live-only constants.** `UNIVERSAL_TARGET_SERVICE` (C3) and the
  `Input` casing/encoding (C6) are derived from AWS documentation and the
  botocore model, **not** from anything `cdk synth` can validate — CDK's only
  checks are "service is lowercase" and "action is camelCase and not
  read-only-prefixed". A green synth suite therefore proves *nothing* about
  them. Do not mark R7/T16 PASS on synth evidence; only a real
  Scheduler-driven invocation counts.
- **Two different `bedrock-agentcore` strings, on purpose.** C3 is
  `bedrockagentcore` (SDK serviceId, spaces stripped) and C4 is
  `bedrock-agentcore` (IAM signing name). An auditor "fixing" one to match the
  other reintroduces the exact defect the contract documents. Both must be
  asserted independently (T4 and T8).
- **CDK's default is the bug.** Without explicit `policy_statements`, CDK
  attaches `Resource: ["*"]` *and* the wrong IAM prefix. T9 is the regression
  test for that; treat any wildcard appearing in this stack as HIGH severity,
  not a style nit.
- **`AWS::SSM::Parameter::Value<String>` is a template *parameter*, not a
  resource.** T12 must not read it as "the stack creates an SSM parameter" —
  the parameter is human-owned and outside CloudFormation by design (C8/C18).
- **Offline-suite invariant.** If the executor ever switches to
  `value_from_lookup`, the tests will still pass on a developer machine with
  credentials and silently start requiring them (and writing
  `cdk.context.json`) in CI. Check the *source* for `value_from_lookup`, not
  just the test result (T15 + C8).
- **Double-fire nuance.** Spec 04's verified 2026-07-28 behavior: a re-invoke
  correctly excludes already-stored cards from `deduped` but still grows the
  table, because `SPIKE_MAX_ITEMS` caps how many *new* items each run
  summarizes. R12/T17 assert "no duplicate card for a given URL", **not** "the
  count is unchanged".
- **Manual-only items**: R7, R8, R12, R13, T16–T19, and the real
  `cdk deploy`/`agentcore deploy`. Mirrors Spec 02's live-Tavily and Spec 04's
  live-deploy precedent.
- **Teardown trap carried over from Spec 04.** Phase 4 redeploys the agent, so
  `agentcore destroy` will `iam:DeleteRole` whatever ARN sits in
  `.bedrock_agentcore.yaml`'s `aws.execution_role` — including the CDK-owned
  one — unless it is nulled first. If the runbook section added by this spec
  omits that, it is a HIGH finding even though the code is correct.
- **Scope discipline.** Any alarm, SNS topic, metric filter, dashboard, Lambda
  bridge, second schedule, or schedule group appearing in the implementation is
  out of scope (Spec 06 / spec amendment) and should be raised as a finding
  rather than accepted as a bonus.
